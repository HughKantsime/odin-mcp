ODIN 2.0.13 MCP compatibility audit

Audited 2026-10-24 against the local odin-2013 source. Package remains odin-print-farm-mcp 2.1.1. No new tools, ODIN edits, publishing, or git writes.

Shared client findings and fixes

  1. Missing Bearer support: add ODIN_BEARER_TOKEN/access JWT and Authorization: Bearer on normal calls and dry-run version probes. API keys still use X-API-Key; explicitly configuring both sends both. No login, renewal, or fallback.
  2. Incorrect global-key guidance: legacy global keys do authenticate as the backend admin. Scoped user tokens remain recommended. Scopes do not override the owning user's role, action matrix, org boundaries, Education guards or license checks.
  3. Errors: ODIN emits structured error.detail objects/lists as well as strings, validation_failed with fields, and plain perimeter detail bodies. Preserve structured details, fields and extras; normalize plain 401/403/404/422/429 bodies to OdinApiError with HTTP status. 429 is retriable; other plain statuses retain http_error unless specifically mapped. Existing structured codes and retriable flags pass through unchanged.
  4. Dry-run documentation incorrectly said unsupported routes execute normally. ODIN refuses unsupported previews. Existing version gate (>=1.9.0), idempotency headers, content lengths and replay detection remain valid for 2.0.13.

Every live tool

All paths below have prefix /api/v1; these share handlers with /api. Every existing tool path and method was valid. R = any of admin, agent:write, agent:read. W = any of admin, agent:write. “+ resource” adds a route-accepted resource scope (broad read/write covers resource scopes). Viewer is the minimum role for reads. Writes require the named configured RBAC action, not merely a scope. JWT and legacy global-key principals bypass token-scope checks while retaining server authorization. Generic role/action checks defer to stacked explicit scope dependencies.

Offline reference tools

reference.calculate_print_cost, reference.compare_farm_software, reference.recommend_printer_for_farm and reference.estimate_farm_capacity (plus their four unnamespaced aliases) use bundled data and local calculations. They perform no REST requests and have no API path, auth, RBAC or HTTP error contract to align. Static market data was outside this source-based compatibility audit.

Response semantics and limits

Read lists retain their established named arrays, single records preserve backend fields, and writes preserve previews, next_actions and replay metadata. Printer counts/filtering derive state from persisted gcode_state and the same 90-second last_seen freshness rule used by ODIN’s UI: RUNNING/PRINTING/PREPARE → printing; PAUSE/PAUSED → paused; FAILED/ERROR → error; IDLE/FINISH/READY → idle; explicit OFFLINE, missing/invalid/stale/future heartbeat → offline; otherwise unknown. Printer objects themselves remain unmodified. Multi-page reads are not atomic snapshots; changing queues may shift between pages. No backend RBAC behavior is simulated as proof of authorization: mocked tests prove request/response handling, while scope/action mapping comes from source.

Verification

npm run build: passed. npm test: 55 passed, zero failed. Tests cover all 22 live registrations, method/path/query/body, Zod enum and slot constraints, pagination above 500, printer state mapping, overdue maintenance, previews, replay, RBAC/perimeter errors, API key/Bearer headers and validation details.

The sandbox refused listening sockets (EPERM). The existing route-based mock was moved to in-process fetch interception, preserving request recording and handlers without a listening server. Stale-version tests now use their actual isolated mock origin rather than a malformed query-string base URL. No live ODIN calls. Fresh Claude review is unavailable in this execution; the actual diff and this report are ready for the driver to review. No independent review is claimed.
